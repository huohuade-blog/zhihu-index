Transformer中的低秩问题是什么意思？

momo · 发布：2026-01-15T04:32:22+00:00 · 更新：2026-01-15T09:38:46+00:00

查看知乎原文

我也困扰过一段时间，下面我说人话来解释。

首先，Transformer肯定是稀疏的，因为softmax attention机制的问题

大多数数值都被打压到0附近了，每一行值比较大的就几个

全0矩阵是不是超级低秩？rank = 0

那全0矩阵里面有几个值，是不是低秩呢？

不见得

对角线上全是值，这可是满秩

一整行有很多个值，其他行都是0，此时rank=1，算是低秩的极端情况

但Transformer没这种情况，比这个高一点，因为每行都又几个值的

因为softmax的机制，极端情况就是1个值，value = 1，其他等于0.

如果1全部在对角线上，那就是满秩。

每行都有一个1，但是位置都差不多，例如50%的1都在第一个元素

统计一下，1在每行的高频位置就几个，那么这就是低秩

说明大量的行是重复的，冗余的。

进一步说明，模式是很少的，所有token都在关注几个重要token

低秩就等于不好吗？我看也不见得。

我们可以做一个思想实验，强制让token关注自己前面一个token

那么这个情况下，是满秩哦，效果会好吗？ 100%不好

因为这就退化到bigram语言模型了，是历史的倒车。

所以与其说低秩是Transformer的问题，不如说是任务的问题

说明任务就不够难，Transformer不需要动用太多pattern就能搞定

但Transformer的容量是够的，完全可以产生更多pattern来解决更难的任务
