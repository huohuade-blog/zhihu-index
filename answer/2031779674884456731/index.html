如何评价DeepSeek V4架构？

momo · 发布：2026-04-26T09:00:23+00:00 · 更新：2026-04-27T06:32:22+00:00

查看知乎原文

我觉得第一大最重要的变化就是 MLA 被放弃。DeepSeek V2、V3 的时候，MLA 被认为是一个重大创新点。

MLA 的核心思想是把 KV 压缩到同一个 compressed latent space里。例如模型维度2048，K 和 V 的维度加起来就是4096，然后压缩到 512，这就是一个 8 倍的压缩。每个头也就相当于一个 8 倍的压缩，如果之前的 headsize 是 128 的话，压缩之后就是 16，我个人的感觉是，这已经非常低秩了吧？会引发一些低秩的问题。不熟悉架构的朋友可以看看下面的图。

新使用的attention叫做Shared Key-Value Multi-Query Attention（如下图），实际上就是 MQA 的进一步简化，把 Key 和 Value 共享一下。

为什么这么做呢？我想根本上还是想要进一步减小KV cache，下面的图是用 GPT Image 2 直接在老图上改的，真是方便呀，不得不说。我们可以看出来，原版的 MQA 就比 MLA 更省 KV Cache。MLA 要用的 KV Cache 的大小是 MQA 的 2.25 倍，改成新的 Shared Key Value MQA 之后是 4.5 倍。将从 MLA 换成 Shared Key Value MQA 之后，KV Cache 又可以下降 4.5 倍。

但是当时 DeepSeek V2 的 paper 里面说，这个 MQA 的 capability 是 weak，不知道现在 DeepSeek 是否还会坚持这样的观点。既然 MQA 的 capability 是 weak，那为什么还要用呢？还是他们觉得 KV cache 的大小远比 capability 重要？也很想听一听 Deepseek 内部的人来谈一谈他们如何看待这个问题

找到一个罗福莉的解释：MLA架构虽然精妙，但由于将算力与访存压榨到了极致（完美临界点），导致很难再叠加 MTP技术来进一步加速推理。
