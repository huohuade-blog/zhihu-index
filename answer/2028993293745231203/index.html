Skill这个东西相当符合直觉

因为我在用 code agent 的时候，为了给大模型补充上下文，创造相应的文件夹。

这个文件夹干啥，当然会有一个 MD 文件，介绍一下，这里面都是些什么材料。

1. 会用要用到的库的文档。这很重要，因为并不是所有的库都是高频库。低频库就是长尾信息，模型可能见过，但是记不清楚，很容易犯错。所以把对应库的使用文档给模型，可以大幅提高模型的准确率。

2. 会有一些示例代码，让大模型快速参考最佳实践。

所谓的同事.skill，实际上也就是类似的东西。本质上还是一种上下文工程罢了。

这东西显然也还是有不少局限性的：

1. 同事走了，同事的文档就不会再更新了。所以同事.skill 是没有成长性的，而且会过时。

2. 同事的很多默会知识是不会留下文档的。所以，你获得的也仅仅是同事所有能力和知识中的冰山一角。

这事真的有意要对抗，一点都不难：

1. 一种方式是再也不要好好写文档了，所有的默会知识都要烂在肚子里，只交付最终结果，所有中间过程全部删除。这样别人想取代你的时候，就会损失大量信息，造成最终的效果不佳。

2. 另一种方式，一边写代码，一边工作，一边脱敏。当部分工作完成后，就对之前的所有信息进行脱敏。例如用一些正确的废话替代。这样别人想取代你的时候，他们只会得到正确的废话。

3. 前两种都不会有任何法律风险。当然，你还可以做得更极端一点，但可能有后续的法律风险，这里我就不说了。
